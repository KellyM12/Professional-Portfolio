## Coding Education

As much as people like to complain about them, coding standards are really the backbone of learning how to code and being able to code effectively with other people. Good naming conventions and commenting are extremely important so that the programmer can remember what certain variables are meant to store and what the functions/methods are meant to do. Even when I was first learning programming, learning and keeping with the coding standards made it easier for me to remember what’s more important for which language (if enters and spacing were important, where to look for functions and the main method, etc.). Coding standards are also helpful for working on projects that involve multiple people. Making sure that there are comments that explain thoroughly what each thing is meant to do can save other people a lot of time when looking over the code. Good, or at least consistent, naming conventions across a group, can also help convey what something is meant for, even if the comments are weak, are absent, or don’t make much sense. However, I think having good commenting conventions is the most important part of coding standards.

## A Memory From a While Ago

During the fall semester of my junior year in high school, I decided to take an intermediate computer programming class that worked in Java at a local college. I was the youngest student, so I stood out quite a bit. Everyone in the class was nice, but sometimes people would try to ask for my help on part of an assignment. I was a bit of a neat freak, so I had decent naming conventions and good comment etiquette at the time. I would always say that even if the comments aren’t in the best state, at least for the draft it should be able to convey what you were doing, so that in the future it would help you remember what you were working on previously. Our professor also emphasized the importance of good commenting, as it was a decent chunk of the grade. I thought that it was good for education, and I learned even more about good commenting.

## The Understandable

Although I’m a staunch believer in having brackets on new lines to a degree that some find concerning, even I can see that sometimes coding standards can seem unnecessary. This week, I tried using ESLint for the first time. I appreciated how thorough the error messages were, which meant I wasn’t guessing why an error was triggered most of the time. However, things like using single quotes instead of double quotes, having a space before each comment, and especially not being able to have brackets on their own separate line, seemed arbitrary. For a beginner in coding, I could see how that could be very off putting. Some people are the type that like to go with the flow, and while I can see those types of people running into problems from that, sometimes good compromises are needed.

## The Important Bit

Overall, good coding standards are important to learn how to work with other people, yourself, and your coding language education. I think emphasizing the main importance of good coding standards are a key for good communication for people learning coding and computer programming for the first time. Most people will agree to try something if they can see why it can be useful, helpful, or important. I found it a bit difficult to install ESLint, but I enjoyed my time with it, and I hope I can work with it more in the future.
